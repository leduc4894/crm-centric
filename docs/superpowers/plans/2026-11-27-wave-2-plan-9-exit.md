# Wave 2 Plan 9 — Exit Verification and Benchmark Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task by task. One coding agent at a time per AGENTS.md. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Thu thập evidence trên candidate xác định để đánh giá Wave 2 exit, gồm full suite trên GitHub CI, benchmark contact list và traceability; báo mọi gate fail/deferred đúng thực tế.

**Architecture:** Đối chiếu contract, migration, auth/tenant, CRUD, tags/fields, timeline và UI với acceptance matrix; sửa sai sót bằng test tập trung trước khi đóng băng candidate. Full suite và security/aggregate chạy trên GitHub Actions của candidate; benchmark chạy riêng trên môi trường có tài nguyên được mô tả, dùng API/auth/DB thật và synthetic data. Không dùng kết quả của commit khác, seed fixture hay scoped review cũ như bằng chứng pass.

**Tech Stack:** Git/GitHub Actions `.github/workflows/wave0.yml`, .NET 10, PostgreSQL/Testcontainers, Keycloak, Python, React/TypeScript, Vitest, Playwright; benchmark harness nhỏ, pinned toolchain và thống kê có thể tái lập.

**Spec:** [Wave 2 design](../specs/2026-11-27-wave-2-crm-contacts-design.md); [roadmap](../../roadmap/01-BACKLOG.md); [acceptance matrix](../../engineering/03-ACCEPTANCE-MATRIX.md); [TDD acceptance](../../engineering/01-TDD-ACCEPTANCE.md); [Plan 8 handoff](../../handoff/2026-11-27-wave-2-plan-8-handoff.md); [Plan 7 handoff](../../handoff/2026-11-27-wave-2-plan-7-handoff.md).

## Global Constraints

- Full test suite **chỉ chạy trên GitHub CI tại Plan 9**, không chạy full suite local. Khi sửa một lỗi được xác định, chỉ chạy local tests liên quan theo RED → GREEN → refactor; full suite sau sửa chỉ rerun GitHub CI. Không tắt required jobs, coverage, scanner hoặc thay đổi trusted baseline để tạo pass.
- `wave0.yml` hiện chạy `pull_request` và `push` vào `main`, chưa có `workflow_dispatch`. Dùng PR thật với event/base/merge/candidate SHA có thể chứng minh; push/PR là hành động remote thuộc việc thực hiện plan khi được yêu cầu, không phải bằng chứng đã xảy ra. Không merge, deploy hoặc thay branch protection chỉ vì chạy CI.
- Tất cả jobs, test counts, skips và benchmark phải gắn exact product candidate SHA, actual base/merge SHA và artifact/run ID; mọi sửa code, contract, config hoặc test sau run đòi hỏi candidate mới và rerun gates bị ảnh hưởng. Docs-only evidence commit không được chuyển verdict sang SHA mới; ghi rõ SHA được kiểm chứng và SHA tài liệu.
- Plan 8 focused review completed theo handoff nhưng đã có một test boolean thất bại khi chạy song song, rerun pass, root cause chưa xác định. Không xóa failure hay gọi flaky vô căn cứ; điều tra nếu tái hiện, bảo đảm full hosted suite không bỏ qua test đó.
- Security hiện **FAIL/deferred**, không waiver/PASS. Hosted run có thể tạo verdict mới: đọc và báo kết quả thực. Aggregate fail do security vẫn FAIL; không gọi overall CI pass. Không coi defer security tự động cho phép đóng Wave 2 hay P0; đối chiếu exit criteria và quyết định user đã ghi, trình bày conditional readiness riêng nếu phù hợp.
- P0 chỉ done sau remote DemoModule E2E, concurrent duplicate, tenant isolation, outage/recovery và restore drills theo AGENTS.md. Các yêu cầu Wave 3–5 chưa triển khai không giả lập thành P0 pass. Benchmark không thay runtime permission/concurrency/audit tests.
- Không log secrets, bearer tokens, connection strings, raw PII hay raw query payload; synthetic data, isolated resources, read-only review trước các thao tác remote, teardown có giới hạn. External module không share DB hay project references; tenant từ verified context.

## Review Focus

1. CI xanh nhưng suite thiếu discovery, skip hoặc contacts/real OIDC test không chạy: gate phải đóng với reason/correlation và evidence count; không suy PASS (Tasks 1, 3).
2. Actual base, merge tree, tested head hoặc scoped compatibility approval hết hạn/lệch: báo review-required, không lấy reviewed-breaking verdict từ Plan 3 cho candidate mới (Tasks 1, 3).
3. Endpoint trả lỗi nhanh dưới tải, user chưa authenticated hoặc tenant/filter sai: benchmark không tính 4xx/5xx/timeout như latency thành công; đo và hiển thị error rate, validate dữ liệu và permission (Task 2).
4. Tenant A/B, RLS/pool, race version/no-op/audit/outbox và browser state: evidence thật gắn tests/commit, không đóng worker/replay isolation trước Wave 3 (Tasks 1, 3–4).
5. Failure không ổn định của form boolean, missing ETag hay sibling refresh: bảo toàn original fail, điều tra theo evidence, không rerun đến xanh rồi xóa lịch sử (Tasks 1, 3).

## Task 2: Benchmark contact list với 50.000 contacts / 50 users

**Consumes:** candidate được build từ exact SHA, disposable PostgreSQL/IdP/API thật, 50 active authenticated principals trong cùng tenant. **Produces:** aggregate JSON, sanitized environment manifest và tài liệu tái lập cho từng scenario; không chứa token hay contact data.

- [ ] Viết unit tests `test_p95_nearest_rank`, `test_50_independent_users_start_together`, `test_http_errors_timeouts_and_wrong_tenant_fail_run`, `test_report_contains_no_token_payload_or_connection_string`, `test_empty_or_short_run_cannot_pass`; synthetic response/clock. `python3 -m unittest discover -s tests/Benchmarks -p 'test_contact_list.py' -v` phải RED trước harness và GREEN sau. Đây là **focused harness test**, không phải full suite hay benchmark result.
- [ ] Implement closed-loop harness: 50 workers, mỗi worker giữ credential/session riêng, đồng bộ start, một request đang chạy mỗi worker; warmup 60 giây rồi đo 300 giây, request timeout 10 giây. Thu monotonic end-to-end response latency tính từ gửi đến đọc đủ body; ghi sample count, throughput, error/timeout counts, p50/p95/p99; p95 nearest-rank `ceil(0.95*n)-1` trên successful valid requests và tách lỗi. `p95 < 400ms` là tiêu chí; chỉ coi measurement hợp lệ nếu đủ 50 workers, đủ thời gian/samples và **không có HTTP error, timeout, invalid body, unauthorized hoặc cross-tenant data** trong measured window; nếu không báo FAIL/INVALID và vẫn ghi mọi counts.
- [ ] Dataset ≥50.000 active contacts trong tenant benchmark với phân bố email/tags, updated_at và cardinality được mô tả; thêm tenant B marker để test leakage. Dùng migration/RLS/app role và IdP/token validation như application, không dùng bypass/mock/cache/trực tiếp SQL thay API. Seed deterministic có seed ID, `ANALYZE`, xác nhận bằng SQL counts và tenant; xóa chỉ test-owned isolated DB/containers sau khi xác nhận identity. Test plan phải xác định rõ 50 users là 50 active authenticated identities, không chỉ 50 threads dùng một token.
- [ ] Chạy ít nhất hai scenario tách biệt: (A) `GET /api/v1/contacts?limit=20` theo thứ tự mặc định, (B) filter `q` hoặc `tagId` thực tế theo dataset với selectivity và exact request shape được ghi. Trước đo validate HTTP 200, tenant membership, response shape và marker B không lọt; server cursor/ETag/tenant context giữ như production. Báo p95 riêng từng scenario; Wave 2 backlog không định nghĩa mix/filter bắt buộc, nên phân biệt **A là workload exit được đề xuất**, B là diagnostic bổ sung, không tự đổi acceptance threshold cho B. Không khẳng định mọi truy vấn đạt p95 từ A.
- [ ] Chọn và ghi **trước khi chạy** môi trường benchmark: CPU model/vCPU allocation, RAM, PostgreSQL version/config/storage, API build/runtime, network topology/RTT, workload client host, OS, container limits, SHA, IdP, lockfile, warmup/measurement và time. Không mặc định GitHub shared runner ổn định; nếu không có môi trường có thể đo/tái lập, báo blocker `BENCHMARK_ENVIRONMENT_UNAVAILABLE`, không bịa cấu hình hoặc mua/provision external resources không được yêu cầu. Ghi API/database CPU/memory saturation, warm/cache state và explain plan liên quan. Benchmark có thể chạy ngoài GitHub CI trong môi trường này; user chỉ yêu cầu full **test suite** ở GitHub CI.
- [ ] Thực hiện và lưu aggregate, an toàn khỏi secret/PII; liệt kê command, timestamps, số user/samples, status counts, p95 và artifacts. Benchmark fail/invalid giữ evidence, điều tra với targeted tests/EXPLAIN, sửa có review, chạy lại trên candidate mới; không bỏ run xấu hoặc thay threshold. Không tuyên bố pass từ seed hay query-plan cũ.

## Task 3: Full suite trên GitHub CI và contract governance

**Consumes:** Task 1 coverage matrix, chuẩn bị PR/run, candidate đã commit; Task 2 benchmark bound cùng product tree. **Produces:** exact GitHub run với evidence cho từng gate.

- [ ] Trước remote run, xác minh working tree, PR base/head/merge SHA, event và workflow triggers; PR đối chiếu với actual base, không giả định `workflow_dispatch` tồn tại. Chạy `gh pr view`, `gh run list/view` để thu run ID, attempt, job status; không thay quyền/branch protection. Record nếu event hoặc checkout không thể chứng minh candidate/base.
- [ ] Chạy workflow trên GitHub cho final candidate và theo dõi backend, compose, contracts-sdk, web-browser, security, aggregate và job CI-tests bổ sung nếu Task 1 xác định cần. Lấy artifacts summary có kiểm soát, assert counts, zero unexpected skips, real provider và contacts case executed, verify tenant/permission/concurrency/audit tests là trong run. `tests/CI`/suite khác chỉ được coi là chạy nếu evidence GitHub có lệnh và kết quả; không dùng local targeted result thay full hosted suite.
- [ ] Đọc **actual-base** compatibility result: distinguish `CONTRACT_COMPATIBLE`, `CONTRACT_BREAKING_REVIEWED`, `CONTRACT_POLICY_REVIEW_REQUIRED` hoặc failure; reviewed-breaking không là compatible hay independent enforcement. Nếu cần policy review, dùng ADR/consumer migration/independent authorized process, không copy prior approval sang product tree mới. Record security và aggregate verdict tách biệt; security FAIL/deferred không biến aggregate thành PASS.
- [ ] Khi job fail/cancel/timeout/zero/skip hoặc Plan 8 boolean tái hiện, ghi original run, reason/correlation và sanitized evidence; chẩn đoán có hệ thống. Nếu no access/credential/review authority, báo cụ thể blocker, không bịa pass.
