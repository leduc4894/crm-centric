# Reviewed Schema Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development, task by task; one coding agent at a time. Steps use checkbox (`- [ ]`) syntax. A test must fail for the stated behavior before implementation.

**Goal:** Allow an independently authorized, exact-candidate review of intentional schema and contract breaks without suppressing any required compatibility, security, SDK, consumer or CI gate.

**Architecture:** A trusted coordinator receives a detached review artifact through a capability provisioned outside the candidate, binds it to immutable event base/candidate Git objects and complete content snapshots, and invokes isolated policy evaluators. Immutable old/new evaluators retain their raw verdicts. A separately trusted, version-pinned full-gate collector runs every required check on the same snapshots; the coordinator may classify only an exact, authorized set as `CONTRACT_BREAKING_REVIEWED` without rewriting raw results, and fails closed on missing authority, evidence, tests or unreviewed changes. Until a genuinely independent verifier and protected coordinator are provisioned and reviewed, the existing gate stays unchanged and nonzero for the current schema change.

**Tech Stack:** Python 3.15.2, `unittest`, pinned repo tooling and oasdiff, immutable Git objects, existing `scripts.ci.revision`, `scripts.ci.policy_transition`, `scripts.ci.semantic_worker`, GitHub Actions pinned in `.github/workflows/wave0.yml`. No new cryptography implementation or unpinned dependency.

**Spec:** [Reviewed-schema policy design](../specs/2026-11-28-reviewed-schema-policy-design.md); [Wave 3 design](../specs/2026-11-28-wave-3-integration-kernel-design.md); [Plan 2 handoff](../../handoff/2026-11-28-wave-3-plan-2-handoff.md). ADR-023 is an uncommitted Plan 2 draft and is not a policy approval or an immutable review artifact.

## Current baseline and trust boundary

- `compatibility.py:run()` computes `baseSha` as merge-base of `HEAD` and `--base-ref`, and its `targetSha` is the resolved **base ref**, not candidate `HEAD`. New schemas return `SCHEMA_COMPATIBILITY_REVIEW_REQUIRED` before later security/oasdiff/SDK checks. Existing `reviewed_contact_change` is an exact historical candidate-owned exception with opt-in, base, expiry, content/evidence hashes; it is not independently verified. The oasdiff loop returns on the first breaking finding. Current CLI treats `CONTRACT_BREAKING_REVIEWED` as exit 0: any new use has mandatory gate implications.
- `.github/workflows/wave0.yml` runs on pull requests/pushes with read-only contents, full checkout and pinned actions. `scripts.ci.jobs` executes the candidate checkout's compatibility script after contract tests, SDK generation check and packaged consumers. `scripts.ci.revision` validates PR merge-parent/event identity. There is **no demonstrated external protected verifier/approver in this workflow**. A candidate-owned file, mutable workflow, environment variable, `--mvp-reviewed-policy`, user direction or historical `independentVerification: false` record is not independent authorization.
- `scripts.ci.policy_transition.GitSnapshotCapability` and `verify_transition` already accept externally provisioned verification capability and immutable Git snapshots; `Plan3SnapshotEvaluator`/`semantic_worker.py` isolate evaluation. `evaluate_transition` currently only accepts both policies as compatible. `Plan3SnapshotEvaluator`/`semantic_worker.py` return a single reason, so a baseline early return does not prove later checks ran. Preserve that raw verdict, explicitly mark its coverage incomplete, and run the separately trusted full-gate collector; never rewrite the baseline evaluator to pretend it executed checks. Do not expose a candidate-controlled verifier on CLI.
- Local starting worktree: `wave-3`, HEAD `60136693c24886f8fa65826185e8a6b80f3f45d8`, 555+ uncommitted entries for Plan 2. They are **not** an immutable approved candidate. `compatibility.py --base-ref 6013669` currently exits 1 `SCHEMA_COMPATIBILITY_REVIEW_REQUIRED`; do not replace this observed result with a fabricated reviewed approval.

## Trusted event mapping and attestation timing

- Existing `RevisionContext` contains no event kind or merge method. A new `VerifiedEvent` wrapper carries the immutable `RevisionContext`, independently authenticated event kind, event provenance and a distinct `integration_method`; it is created only by a protected coordinator, never inferred from candidate input or merely from `merge_sha`.
- PR: trusted event `pull_request.base.sha` → `base_sha`, `pull_request.head.sha` → `head_sha`, run-bound `GITHUB_SHA` → `candidate_sha = merge_sha`; checkout equals candidate and candidate parents must be exactly `[base_sha, head_sha]` with `merge_base_sha = base_sha`. This synthetic merge is a CI candidate shape, not proof of the eventual repository merge strategy. For reviewed PR eligibility, the eventual strategy (`merge`, `squash` or `rebase`) is separately supplied and authenticated by the trusted approval capability and must match the approved record; do not infer it from CI merge parents.
- Push: trusted event `before` → `base_sha`, `after` → `head_sha = candidate_sha`, `merge_sha = null`; checkout equals `after`, `forced` must be exactly false and `merge_base_sha = before` (non-forced ancestor). `integration_method` is JSON null / not applicable and must not accept `merge`, `squash` or `rebase` as if derived from push. Current push path does not independently validate `GITHUB_SHA`; do not claim it does.
- Attestation is issued only **after** the exact event candidate commit and tree are immutable and proven by the trusted event source. Bind event, base/head/candidate/tree and applicable method; changed base/head or a newly generated synthetic merge invalidates it. Missing, unauthenticated or ambiguous event provenance, missing candidate/tree or absent reviewer authority fails closed; a synthetic test event is not a protected event source. No real trusted source is currently evidenced.

## Global Constraints

- No exceptions, auto-approval, skipped checks or changed verdicts from source the candidate controls. No real approval is synthesized, and no privileged key, secret or token is printed, committed or exposed to candidate code.
- Bind actual event base and the exact candidate commit **and tree**, head and merge identity; preserve all legacy `targetSha` semantics and add unambiguous `candidateSha`/`candidateTree` fields. PR synthetic merge and push event must be separately verified. Reject dirty local snapshots and candidate drift.
- Materialize immutable Git blobs with `--no-replace-objects`, no lazy fetch, validate all paths/types/symlinks and hash complete, sorted base/candidate OpenAPI and JSON Schema sets plus transitive local refs. Review identity also binds ADR, policy/generator/tool configuration, generated SDK and consumer evidence, all scope/findings and expiry.
- Schema review, breaking API/SDK review, mTLS/token security review and policy-source change review are distinct scopes; an authorized record must cover each exact discovered finding. No pass if a required check failed, skipped, timed out, was unavailable, or yielded additional/unrecognized findings.
- Keep security scanner, aggregate, all required CI jobs and full suite enabled. A `reviewed-breaking` classification is not `compatible`, deployment clearance, security clearance, or P0 acceptance. Do not implement a mechanism that automatically changes a required job to success; the exit-0 policy requires independently approved trusted CI integration.
- Deterministic signed payload encoding is UTF-8 `json.dumps(payload, sort_keys=True, separators=(',', ':'), ensure_ascii=True, allow_nan=False)` after strict duplicate/unknown-key/type validation. SHA-256 digests are lowercase 64-hex, Git IDs are exact lowercase 40-hex, timestamps are integer UTC seconds. Test keys are synthetic and public; no custom crypto in production. Fail closed when trusted external signature verification or revocation is unavailable.
- Keep working tree's unrelated, uncommitted Plan 2 files intact; never commit them as policy changes. Make isolated task commits; actual candidate and later detached approval must not form a self-referential commit.

## Review Focus

1. PR synthetic merge/head/base substitution and clean-looking dirty input — test exact event identity and dirty/symlink rejection in Task 1.
2. Malformed or replayed signed review, duplicate JSON, extra paths, expiry/revocation, changed reference/ADR/SDK bytes — test tampering in Task 2.
3. Candidate-controlled verifier, policy or workflow claiming its own approval — test trust capability absence/forgery and dual-policy isolation in Tasks 2–3.
4. Early return after approved schema hides mTLS security change, extra oasdiff finding, skipped SDK or failed consumer — test complete outcomes and nonzero behavior in Task 3.
5. Synthetic approval mistakenly reaches real required CI or grants acceptance — test disabled-by-default workflow/exit behavior and explicit blocked integration in Task 4.
