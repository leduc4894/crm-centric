# Local finding adjudication kernel — not deployed

User authorization permits continuing design and tests for exactly the 64 records in the [review proposal](2026-11-12-mvp-secret-review-proposal.md). It supplies neither an independently operated approval capability nor independent JAR evidence. The proposal's historical PENDING text remains the record of the original session. No currently blocking finding has been cleared.

`scripts/ci/finding_adjudication.py` is an isolated, in-memory dependency seam. Neither scanner verdicts nor workflow execution import it. Default invocation has no capability and blocks every record. There is no decision-file loader, receipt, trust key, production adapter, scanner ignore or CI bypass. A Python object implementing the seam is not authenticated merely because it has the expected methods. Candidate code can construct such objects; this local kernel cannot defend an independent host that executes candidate-controlled code.

Before adoption, an independently administered verifier must acquire the exact verified candidate and immutable verifier implementation, bind scanner version/binary/configuration identity, validate the complete reviewed 64-ID inventory and per-record multiplicity, and provide its independently authorized per-ID decisions. Decisions bind candidate, scanner version, scanner binary SHA-256, configuration SHA-256, fingerprint, file, structural member, line, rule, owner and expiry. The host must reject arbitrary IDs, candidate-authored policy and substituted sources. This administrative boundary remains **unprovisioned**. The local Context is an interface for already-verified identity, not a proof of executable/configuration authenticity or snapshot identity.

The kernel accepts only the five proposed file shapes. It rejects duplicate JSON keys, malformed JSON, repeated selected member names in different objects, extra line/match content, changed fingerprints/locations/multiplicity, source mismatches, missing/invalid/expired decisions and every history record. Contract references are bytes in the independently verified candidate snapshot. JAR bytes must come from the independent provider, never the local distribution or metadata itself. No independent JAR source is available here; all 60 actual JAR findings remain blocked. Synthetic JAR positive tests demonstrate the seam only.

Each input record is preserved with its origin and decision, bounded reason token and correlation ID; successful synthetic decisions also retain owner and expiry. Native records remain private in memory. Do not serialize the entire result into public evidence: use the existing safe-publication boundary for opaque IDs and bounded conclusions. Raw native records, matched values and scanner stderr are never printed by these tests.
