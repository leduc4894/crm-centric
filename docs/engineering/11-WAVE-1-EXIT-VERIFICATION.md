## Independent review and repairs — 2026-11-26

The independent reviewer examined `40bc290..e43d2e9` and reported two findings; this was scoped static review, not an exhaustive audit. First, same-audience signed ID tokens could authorize tenant and membership endpoints because those routes omitted the existing access-token metadata. The test `dotnet test tests/Integration/Integration.csproj -c Release --no-restore --filter 'FullyQualifiedName~Same_audience_id_token' --logger 'console;verbosity=minimal'` failed 5/5 before the fix: tenant list and all three membership routes returned 200, and tenant create returned 201. Commit `9ba62ab` adds the existing discriminator requirement on these five routes. The directly affected `dotnet test tests/Integration/Integration.csproj -c Release --no-restore --filter 'FullyQualifiedName~OidcAuthenticationTests|FullyQualifiedName~TenantEndpointsTests|FullyQualifiedName~TenantProvisioningTests|FullyQualifiedName~MembershipEndpointsTests|FullyQualifiedName~InviteManagementTests|FullyQualifiedName~AuditEndpointsTests' --logger 'console;verbosity=minimal'` passed 72/72, zero skipped. The issuer must still reserve the signed payload `typ` value `Bearer` for access tokens.

Second, the web tenant client counted UTF-16 code units against an API limit expressed in Unicode code points. The new client test failed 1/5 before the fix with `WEB_TENANT_CONTRACT_INVALID` for 200 supplementary characters. Commit `e4201aa` counts code points and checks both 200 accepted and 201 rejected. `npm exec --workspace @crm-centric/crm-web -- vitest run src/tenant/tenantClient.test.ts src/tenant/TenantProvider.test.tsx src/tenant/TenantPicker.test.tsx` passed 15/15; `npm run typecheck` passed. Node/npm required the local libatomic path; .NET used `.local/ci-dotnet`. Both fixes await independent review; final candidate suite/workflows and all previously stated acceptance and security gaps remain OPEN.
