## Decision

Design a fail-closed, independently controlled coordinator for exact-candidate review. It consumes a **detached** attestation from an externally provisioned trusted authority; reviewers cannot use candidate-controlled code, files, flags or environment variables to declare their own work approved. The candidate commit and tree are fixed before attestation; a later separately controlled artifact refers to that immutable candidate, avoiding self-referential commit hashes. A synthetic test capability tests the seam but grants no live authorization. No production algorithm or new unpinned cryptography dependency is selected by this ADR.

The signed review identity must bind all of the following:

- Actual immutable event base, head and candidate commit SHA, candidate tree, event and merge method; both PR merge and push semantics are verified. `targetSha` retains its existing base-ref meaning; candidate identity is reported separately. Dirty local inputs, moved refs, missing Git objects, replacement objects and candidate drift fail closed.
- Exact complete sorted path-to-SHA-256 maps of all base/candidate OpenAPI, JSON Schema and local reference closure, with no missing, added, duplicate, traversing, nonlocal or symlink path. Immutable Git bytes are read without lazy fetch or candidate code execution. Include exact policy/toolchain/generator, ADR/migration, generated SDK, consumer evidence and test result digests required by scope.
- Named reviewer identity and authorized scopes for each schema addition, each breaking API/SDK finding, each security change and each policy-source change; issue time, expiration, revocation state and signature. Use strict duplicate/unknown-key rejection and deterministic UTF-8 JSON encoding as specified in the plan. Approval of one scope never silently approves another. Authority absence, unavailable revocation, expired or mismatched record, unexpected finding or evaluation error remain nonzero.

### Event-specific proof and approval

For a pull request, the existing `resolve_event` maps event PR base to `base_sha`, PR head to `head_sha`, and run-bound `GITHUB_SHA` to `candidate_sha = merge_sha`. The checkout must equal that candidate, its parents must be exactly `[base_sha, head_sha]`, and the merge-base must equal the base. This synthetic CI merge is not proof of eventual integration strategy. For reviewed PR eligibility, a protected authority must explicitly authenticate the eventual integration strategy `merge`, `squash` or `rebase`; it cannot be inferred from the CI merge's parents.

For a push, the event's `before` is `base_sha`, `after` is `head_sha = candidate_sha`, `merge_sha` is null, checkout equals `after`, `forced` must be exactly false and merge-base must equal `before`. The integration method is JSON null/not applicable; no PR method is inferred. The current push path does not separately verify `GITHUB_SHA`. `RevisionContext` carries no event kind or method, so a separate `VerifiedEvent` value from an independently authenticated event-source capability must carry provenance and the appropriate method; neither a candidate-provided flag nor an inferred null merge is that proof.

A detached attestation is issued only after the exact candidate commit and tree exist and trusted event provenance has been verified. It binds event kind, base/head/candidate/tree and applicable method; a changed base/head, regenerated PR synthetic merge, missing event provenance, unproved method or unavailable authority fails closed. This source workspace does not demonstrate the protected event source, signer or real attestation.

### Independent collection beyond early-return policy

Existing `Plan3SnapshotEvaluator` and `semantic_worker.py` return a single raw reason. When the baseline policy sees a new schema it returns `SCHEMA_COMPATIBILITY_REVIEW_REQUIRED` before security, oasdiff, SDK and consumers; record this exact baseline verdict with explicit `INCOMPLETE_EARLY_RETURN` coverage. Preserve the raw candidate policy verdict separately. Do not rewrite the old policy, relabel its nonzero result or claim it ran checks it never reached.

A separately trusted and independently version-pinned full-gate collector must consume the same immutable base/candidate bytes and run each schema/reference, security, pinned oasdiff, SDK and independent consumer check in unprivileged isolated workers without access to approval credentials. Report every check's individual result and coverage alongside both raw policy verdicts. Any missing, skipped, failed, timed-out or unexpectedly changed finding blocks reviewed classification. An exact synthetic approval can test classification of the collector's findings as `reviewed-breaking`; it cannot change a raw baseline failure, prove current CI completion or clear a required check. Actual CI exit behavior remains a separate independently reviewed rollout decision.

The verifier and key/issuer, role mapping and revocation authority must come from a coordinator protected independently of the candidate and be verified by an authorized operator. The separately trusted coordinator must never execute PR code with approval credentials. Candidate-authored policy changes cannot authorize themselves: establish their own exact-digest review and evaluate old and new immutable policy independently against the same real snapshots; preserve their exact verdicts and separately collect full checks as above. Synthetic keys, repo fixtures and an `independentVerification: false` record are not production evidence. These controls do not yet exist in the verified workspace; keep `authority_status: UNAVAILABLE` and the existing mandatory gate fail-closed until they are independently demonstrated.

Schema review is a prerequisite to continue evaluation, not permission to stop it. The separately trusted collector runs full pinned schema/ref validation, security checks, oasdiff, SDK comparison and independent old/new consumers on the exact snapshots; it records complete findings and actual outcomes without changing a historical policy verdict. Unreviewed security change, additional breaking diff, invalid schema, unavailable tool, failure, timeout or skipped mandatory test stays nonzero with a safe reason token and correlation ID. Do not suppress any scanner, required job or aggregate. Only independently authorized evidence covering each discovered finding and all successful mandatory checks can be eligible for a `reviewed-breaking` classification; never call it compatible. Whether this classification may satisfy the existing exit-0 required check is a **separate policy and rollout decision**, not authorized or implemented here. A reviewed contract is not production receiver/provider enforcement, remote DemoModule E2E, security clearance or P0 acceptance.

## Required negative verification

Use synthetic isolated Git repositories, explicitly public test keys and independent test consumers. Tests must show nonzero failure for:

1. One-byte mutation, add/remove/rename or symlink substitution of any schema, OpenAPI, local reference, ADR, generator, policy, SDK or consumer-evidence input; extra/missing paths or duplicate JSON properties.
2. Wrong PR base/head/merge candidate/tree, wrong push identity, dirty input, replaced Git object, missing object, expired/revoked record, replay against another candidate, unavailable authority or ambiguous time.
3. Missing/forged signature, wrong reviewer/issuer/role/scope, candidate-selected verifier, candidate-authorized policy self-change or security finding without separate authorization.
4. Unreviewed oasdiff finding, changed token/mTLS requirement, invalid schema, skipped/failing consumer, SDK surface mismatch, evaluator timeout or missing pinned tool. These remain nonzero even if a schema change was reviewed.
5. Candidate workflow attempting to expose review credentials, execute PR code in a privileged coordinator, change required checks or turn `reviewed-breaking` into compatibility/security/P0 success. Verify structured reports preserve base/head/candidate, individual outcomes, correlation ID and actual failure.

A positive synthetic case proves only the isolated test path. Exact materialized candidate bytes, trusted protected authority and authorized separate review remain necessary before any live reviewed result.

## Rollout and rollback

First implement and independently review disabled-by-default seams and tests in the [plan](../superpowers/plans/2026-11-28-reviewed-schema-policy.md). Separately establish and audit the external coordinator, authority, signing/key rotation, role assignment, revocation and protected CI event binding. Identify an accountable rollout owner and document required-job semantics before integrating a real attestation. If any prerequisite is absent, preserve the present nonzero gate. Do not deploy, merge or publish as a consequence of this ADR.

If the trusted authority, review record, evaluator or policy is found invalid, disable the reviewed path and retain the normal nonzero compatibility/security checks; preserve evidence and original classification, revoke compromised review authority through its independently controlled mechanism, and forward-fix under a fresh exact-candidate review. Do not silently relabel prior breaking, security or aggregate failures as success.
