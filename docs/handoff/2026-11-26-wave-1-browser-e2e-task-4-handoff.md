# Wave 1 Plan 4 — browser E2E task handoff

Objective: execute Task 4 of the [browser OIDC plan](../superpowers/plans/2026-11-26-wave-1-plan-4-browser-oidc.md) on `wave-1`, with focused testing only. Added an opt-in Chromium fixture that builds a unique Compose project and owner, creates disposable Keycloak identities and tenant/staff bindings in its own PostgreSQL, launches Vite, and removes only resources labeled for that owner. Credentials and issued tokens remain in memory; traces, video and screenshots are disabled. Test accounts are random and disposable. No production bootstrap mechanism or public contract was added.

The real Keycloak browser flow completes authorization code + S256, validates A/B tenant visibility, selects A, verifies a same-tenant membership request returns 200 and A against B's tenant returns 403, signs A out and confirms Keycloak requests credentials again. It tests replay, an altered state during a real login with no tenant request, synthetic callback failure, token absence from local/session storage and request URLs, empty IndexedDB, bearer/health routing, provider unavailable, logout failure and expiration via Chromium clock. Real tokens are not printed. The token checks cover tokens returned in the A session; browser execution is Chromium only. Keycloak login and API were real; expired-session passage was simulated by the browser clock. The wrong-state test modifies the Keycloak login redirect in the browser harness; no IdP setting was weakened.
